# Design Document: Open-Source Boosts

## Overview

The engine gets a real domain parser (`tldts`), a Unicode-based homograph check with a small Punycode decoder, and a typosquat check against a generated list of famous domains. All of it lives in `src/detection/`. `analyse()` stays synchronous and keeps its signature. The heavy data (tldts with its Public Suffix List trie, the confusables map and the generated brand list) is measured at about 47 kB gzip for tldts alone, so all of it sits behind ONE lazy chunk named `detection-data`, loaded with a dynamic `import()`. `src/detection/index.ts` exports `ensureDetectionData(): Promise<void>`. The app starts it on idle after first paint; `PossessionCheck` and Séance await it before their first `analyse()`; the test setup awaits it so all 821 existing tests run against the full data. Before the chunk has loaded, `analyse()` uses the curated brands and the old suffix table in a documented, tested pre-load mode. New data files are generated by committed scripts. A dev-only `scripts/eval/` script reuses the real engine to measure precision and recall. A `phishing-forensics` Kiro power and a `detection-tests` hook support the workflow.

I read `brands.ts`, `links.ts`, `normalise.ts`, `analyse.ts`, `registry.ts`, `lookalike-domain.ts`, the callers of `analyse()` (`PossessionCheck.tsx`, `seance/feedback.ts`, tests), the existing hooks and `tests/repo-conformance.test.ts`. Today `registrableDomain` and `suffixLabelCount` in `links.ts` use a hand-made list of second-level labels, `normalise.ts` has about 40 hand-picked confusables, and `findBrandLookalike` in `brands.ts` matches only the 21 curated brands. `ghost-effects.ts` (a feature) also calls `lookalikeParts`, `parseHost` and `registrableDomain`, so their signatures must stay.

## Key decisions

| Decision | Choice | Reason |
| --- | --- | --- |
| Sync or lazy data | ONE lazy chunk `detection-data` holds `tldts`, `confusables.ts` and `top-brands.ts`, loaded with `import('./data-bundle')` from `src/detection/data-loader.ts`. `analyse()` stays synchronous. `ensureDetectionData(): Promise<void>` is exported from `src/detection/index.ts`. | tldts alone is 47 kB gzip (measured), about twice the whole 25 kB budget, so it cannot sit in the main chunk. One chunk keeps one loading state. Making `analyse()` async would touch every caller and test, so it is not done. |
| Loading protocol | The app (`src/main.tsx` or the shell) calls `ensureDetectionData()` from `requestIdleCallback` (fallback `setTimeout 0`) after first paint. `data-loader.ts` also exports a sync `isDetectionDataLoaded(): boolean` (re-exported from `index.ts`). `PossessionCheck.check` and the Séance answer handler `respond` (Séance has no "start" handler: `Seance.tsx` calls `feedbackFor` inside a `useMemo` and inside `respond`) run synchronously when `isDetectionDataLoaded()` is true, and otherwise `await ensureDetectionData()` first and then continue; this keeps today's click-then-assert tests synchronous. The `useMemo` call only runs after a guess exists, so it is already behind `respond`. The existing `src/test-setup.ts` (it already registers `cleanup()` in `afterEach`) is EXTENDED to await `ensureDetectionData()` once in `beforeAll`, so every existing test and property test sees full data. A failed dynamic import (offline, blocked) resolves the promise without data and leaves pre-load mode active; it never rejects into the UI and a later call retries. | Callers cannot wait on `analyse()`, but they can wait before calling it. |
| Pre-load mode (the only degraded mode) | Until the chunk has loaded, `domain.ts` uses the old suffix table (the former `SECOND_LEVEL` logic, kept in `domain-fallback.ts`) and `findBrandLookalike` runs the curated checks only (steps 1 to 4 and the typosquat check against curated keys with the curated hand-made stand-ins in `normalise.ts`). It throws nothing. Steps that need `confusables.ts` or `top-brands.ts` are skipped. The documented rule: results for inputs that need no data are identical before and after load; results for inputs that need data (generated brands, full confusables, PSL-only suffixes) may gain flags after load. After load, `analyse()` is deterministic for the life of the page. A test pins both modes. | Honest and testable. The user-facing path never analyses before load because the handlers await it. |
| tldts package | `tldts` 7.4.19, imported as `import { parse } from 'tldts'` inside `data-bundle.ts` only | Maintained, typed, same hostname handling in jsdom and browsers (no `URL` dependency), tree-shakeable ESM. `tldts-core` has no PSL data. No smaller variant is assumed; `tldts-experimental` is not used (unverified). |
| tldts options | `{ allowPrivateDomains: false }` | `myshop.blogspot.com` is then judged as `blogspot.com`, so hosted pages are not mistaken for separate organisations. |
| Punycode | Own `punycode.ts` (RFC 3492 decoder, about 60 lines, no encoder) | `URL.domainToUnicode` differs between jsdom and browsers and the npm `punycode` package is deprecated in Node. A decoder is small and fully testable. |
| Confusables data | `scripts/gen-confusables.mjs` writes `src/detection/data/confusables.ts` | Extraction rule (exact): parse each data line; keep an entry when (1) the source is a single non-ASCII code point, (2) the target string, lower-cased, matches `^[a-z0-9]{1,2}$` (lower-casing happens BEFORE the filter, so `A` and `I` prototypes are kept as `a` and `i`), and (3) one pass is a fixed point: drop an entry if its lower-cased target contains any source key of the kept map, so `skeleton(skeleton(x)) == skeleton(x)`. Multi-code-point sources are dropped. Expected 1,000 to 2,000 entries, about 8 to 14 kB raw and under 6 kB gzip. The file is part of the `detection-data` chunk. |
| Existing `CONFUSABLES` in `normalise.ts` | Keep, and merge: generated map first (once loaded), then the hand-made ASCII stand-ins (`0 1 3 5 |`, `rn`, `vv`), which are always active, also in pre-load mode | The ASCII digit stand-ins are not in `confusables.txt` as Latin targets. Existing normalise tests keep passing. |
| Typosquat data | Majestic top 1,000 into `src/detection/data/top-brands.ts` (about 14 kB raw, about 6 kB gzip), only if the Majestic licence sentence is read (see Evidence). Otherwise a curated-only list | 5,000 would be about 30 kB raw and adds many generic words that raise false alarms. 1,000 covers the sites people actually imitate. `gen-brands.mjs` has a documented `EXCLUDE` deny-list (adult sites, ad networks, URL shorteners, generic infrastructure domains) applied before the cut, and prints how many rows it dropped. The file is part of the `detection-data` chunk. |
| Priority | Curated `BRANDS` are checked first and own the wording. Generated brands feed the typosquat check, plus one narrow homograph check (see Detection logic step 4). ## Components and files

New:
- `src/detection/data-loader.ts`: holds the loaded-data state, `ensureDetectionData()` (cached promise, dynamic `import('./data-bundle')`, never rejects) and `getData()` returning the loaded data or `undefined`. `src/detection/data-bundle.ts`: the only file that imports `tldts`, `data/confusables.ts` and `data/top-brands.ts`; it is the entry of the `detection-data` chunk. `src/detection/domain-fallback.ts`: the old suffix logic for pre-load mode. `src/test-setup.ts` (referenced from `vite.config.ts` `test.setupFiles`) awaits `ensureDetectionData()`.
- `src/detection/domain.ts`: `parseDomain(host)` returns `{ host, registrable, name, suffix, subdomain, isIp }`. Wraps `tldts`, never throws, lower-cases and trims, strips a trailing dot, returns the host itself for IPs and hosts without a public suffix. It passes the host to `tldts` in the form received (Unicode or `xn--`; tldts does its own IDNA handling) and returns `registrable`, `name` and `suffix` in that same form, with no decoding. Expected: `pаypal.com` (Cyrillic а) returns registrable `pаypal.com`; `xn--pypal-4ve.com` returns itself; `дом.рф` returns itself; `paypal.com.secure-login.xyz` returns `secure-login.xyz`. Task 1.2 verifies these against the installed `tldts`; if it behaves differently the table here is corrected and `parseDomain` normalises to the form above. Callers that need the decoded form call `toUnicodeHost` first.
- `src/detection/punycode.ts`: `decodePunycodeLabel(label)` and `toUnicodeHost(host)`. Decodes only labels starting with `xn--`. On any error returns the input unchanged.
- `src/detection/skeleton.ts`: `skeleton(text)` maps through the generated map (when loaded) and the existing stand-ins, and `scriptsOf(text)` returns the set of scripts used in a label. `scriptsOf` uses Unicode property escapes: characters with `\p{Script=Common}` (digits, hyphen, punctuation) or `\p{Script=Inherited}` (combining marks) are ignored; `\p{Script=Latin}` counts as Latin, accented letters included; any other character counts as its own `\p{Script=...}` (Cyrillic, Greek, Devanagari and so on). A label is "mixed" only when it has two or more distinct scripts after ignoring Common and Inherited. So `bank-1.in` and `café.in` are single-script (Latin) and not mixed, while a Latin plus Greek label is mixed.
- `src/detection/typosquat.ts`: `findTyposquat(domain)` using the edit-distance rules below.
- `src/detection/data/confusables.ts`, `src/detection/data/top-brands.ts`: generated, with headers, imported only by `data-bundle.ts`. `confusables.ts` writes every source character as a `\uXXXX` (or `\u{X}`) escape so no raw look-alike or invisible character sits in the file and ESLint rules such as `no-irregular-whitespace` and `no-misleading-character-class` stay quiet (finding 14). They are normal TypeScript that lint and typecheck cover (typed `as const` arrays, no ignore entries), and they carry a "GENERATED, do not edit" header.
- `src/features/possession-check/to-analysis-input.ts`: pure `toAnalysisInput(parsed: ParsedEmail): AnalysisInput`, used by the screen and by the eval script (see Evaluation script). `src/email/` keeps working on strings only and does not import `src/detection`.
- `scripts/gen-confusables.mjs`, `scripts/gen-brands.mjs`: PowerShell-runnable, use Node `fetch` at dev time only. They live in `scripts/`, which is not shipped. Runtime code still has no `fetch`.
- `scripts/eval/run.ts`, `scripts/eval/mbox.ts`, `scripts/eval/README.md`, `scripts/eval/fixtures/`.
- `powers/phishing-forensics/`, `.kiro/hooks/detection-tests.json`, `docs/EVAL.md`, `THIRD_PARTY_NOTICES.md` (new at the repo root; it does not exist yet, so it is created with the existing Creepster, tesseract.js, tesseract.js-core and eng data entries from `public/licenses/`).

### No new rule ID

Homograph, subdomain trick and typosquat all produce flags of the existing type `lookalike-domain`. Reason: `FLAG_TYPES`, the Exorcism plan (`STEP_TRIGGERS`), ghost kinds and the Séance topics already key off this type, so a new type would ripple through the UI and several tests. The user sees the new cases through new reason wording. The rule count stays at 17 rule files, and no test that counts rules changes. The brief task 3 allowed either a new rule file or extending `lookalike-domain.ts`, and extending it is chosen.

## Detection logic

Two brand sets are used. **Curated** means the keys of `BRANDS` in `brands.ts` (India-focused, existing). **Generated** means the registrable names in `top-brands.ts`. Generated names are only usable as a match target when `name.length >= 6`.

`findBrandLookalike(host)` runs these steps in order (the first hit wins; the whole body is inside a guard and never throws):
1. IP or empty host: no match.
2. `d = parseDomain(host)`. If `d.registrable` is in a curated `official` list or in the generated list: no match.
3. Decode `xn--` labels with `toUnicodeHost`; `decoded` is the result. Let `name` be the decoded registrable name.
4. **Existing curated check, unchanged** (`folded === key`, near-miss, contains, hyphen pieces) against curated keys only. A hit keeps kind `brand`, so every old test and sample verdict is unchanged. The existing `skeleton` merge only widens what `folded` can see.
5. **Homograph**: compute `skeleton(name)` over the whole registrable label (not a hyphen piece). If it equals a curated key, or equals a generated name of length 6 or more, and the raw (decoded) label differs from that brand name (so it contains at least one confusable character, as defined under Edit-distance thresholds: non-ASCII or one of `0 1 3 5 | rn vv`), return kind `homograph`. Plain ASCII labels such as `my-office-deals` or `office` never reach this match.
6. **Brand in subdomain**: only for curated keys. If a whole label of `d.subdomain` has a skeleton equal to a curated key and step 2 did not return, return `brand-in-subdomain` (for example `paypal.com.secure-login.xyz`, judged as `secure-login.xyz`). `mail.example.com` and `news.example.org` cannot match because `mail` and `news` are generated names, not curated keys.
7. **Typosquat**: runs on `skeleton(name)` of the decoded name, so it never sees non-ASCII input. `gооgle` with a Cyrillic о is caught by step 5 first. Candidates: curated keys plus generated names. See thresholds.
8. **Foreign script**: only if the decoded host has a label that is mixed (two or more distinct scripts per `scriptsOf`, ignoring Common and Inherited) or an `xn--` label that cannot be decoded. A single-script label (Devanagari, Tamil, Cyrillic-only, or Latin with accents) is NOT flagged unless its skeleton equals a brand in step 5. `bank-1.in` and `café.in` are not flagged.

**Deliberate behaviour change.** Today `findBrandLookalike` returns `foreign-script` for any non-ASCII character or any `xn--` label. This design narrows it to the cases above. A single-script non-brand host that was flagged before is no longer flagged, and an undecodable `xn--` label is a new explicit flag. The old reason text ("mixes in letters from another alphabet") fits mixed labels only; the undecodable case gets its own wording ("This web address uses an encoded name that could not be read, so check who sent it."). No existing test pins single-script non-ASCII (checked by search), so task 2.4 adds tests for each case, and the journal task lists this as a deliberate change.

**Pre-load mode.** Steps 5 to 7 use the generated confusables and generated brands. Before `ensureDetectionData()` resolves, step 2 and step 3 use the old suffix table, step 4 runs as today, step 5 and 7 use the curated keys and the hand-made stand-ins only, and step 6 and 8 run on the stand-ins. Inputs that need no data (curated hits such as `paypa1.com` and `hdfc-bank.xyz`) return the same result before and after load; a determinism test checks this.

The existing `imitation` flag stays: it is true when the raw label is not a plain brand name.

### Severity and match kind

| Kind | When | Severity |
| --- | --- | --- |
| `brand` | Existing curated hits, unchanged (`paypa1.com`, `hdfc-bank.xyz`) | high (unchanged) |
| `homograph` | New confusables or punycode path, curated or generated target | high |
| `brand-in-subdomain` | Curated brand label in front of another registrable domain | high |
| `typosquat` | Distance 1 or 2 from a curated or generated name | medium |
| `foreign-script` | Mixed scripts in one label, no brand | medium |

`reasonFor` and the severity line in `lookalike-domain.ts` become a switch on kind. Old curated cases keep kind `brand`, so existing tests do not change; `homograph` appears only for cases the old map could not see. The sample tests that pin verdicts are the regression check.
### Edit-distance thresholds

Let `a` be `skeleton(decoded registrable name)` of the candidate (lower-case ASCII) and `b` be `skeleton(brand registrable name)`. Both sides are skeletonised. Use `levenshtein` (already in `brands.ts`).

"Is the brand" is decided only by raw registrable-domain equality (Detection logic step 2), never by skeleton equality. A **confusable character** means any character or sequence that `skeleton()` changes, including the ASCII stand-ins `0 1 3 5 |`, `rn` and `vv` as well as every non-ASCII source in the generated map. So `g00gle.com` and `paypa1.com` (skeleton equals the brand, raw differs) are never "the brand": they reach step 5 and are flagged `homograph`.

| Case | Rule |
| --- | --- |
| Raw registrable domain equals a Brand_Domain | It is the brand: never flagged (step 2, before any skeleton work). |
| Skeleton distance 0 but raw differs (`g00gle.com`, `paypa1.com`, Cyrillic `а`) | Not a typosquat: it is a `homograph` (step 5). A test asserts `g00gle.com` (generated brand `google`) is flagged `homograph`. |
| Same name, different suffix (`paypal.xyz`) | Not a typosquat. The curated check may still flag it as before. |
| Distance 1, curated brand, added or dropped letter | Flag when `a.length >= 5` and `b.length >= 5`. |
| Distance 1, generated brand, added or dropped letter | Flag when `a.length >= 6` and `b.length >= 6`, the first letters are equal, and the length difference is at most 1. |
| Distance 1, same length (one letter changed), curated or generated | Flag only when `a.length >= 8` and `b.length >= 8` (plus the first-letter rule for generated brands). Changing one letter of a short word often gives another real word (`ample`/`apple`, `forges`/`forbes`). Constant `MIN_LENGTH_SAME_LENGTH_D1` in `typosquat.ts`. |
| Distance 2 (curated or generated) | Flag when `a.length >= 8` and `b.length >= 8`, the first letters are equal. |
| Short or common words | Names under the minimum above are never compared (`ebay` vs `ebat`, `bbc` vs `abc`). |
| Candidate is itself listed | If the candidate's registrable domain is in the curated or generated list, never flagged (two real sites such as `tumblr` and `tumbler`). |
| Length gap over 2 | Skipped before computing distance, which keeps the check cheap for 1,000 brands. |

Trade-off, stated in the journal: a legitimate small site one letter from a famous one can still be flagged at medium severity. The reason says "a small spelling change away from X" and "if you did not expect this, do not trust it" rather than saying it is fake. A regression test holds at least 30 ordinary real domains that must not flag, including `ample.com`, `median.com` and `forges.com`.
Wording (one line each, no certainty):
- homograph: `This web address copies PayPal's name with look-alike letters, so it may not be PayPal's real website.`
- homograph with decoding: `... Decoded from xn--pypal-4ve.com: pаypal.com.` The decoded host is plain text appended to the reason. Because the decoded text may contain non-ASCII characters, it is shown inside the existing flag reason as text only. It is never an `href`.
- brand in subdomain: `This web address puts PayPal's name in front of a different website (secure-login.xyz), so it may not be PayPal.`
- typosquat, curated brand (has a display name): `This web address is a small spelling change away from hdfcbank.com, so it may be an imitation of HDFC Bank.`
- typosquat, generated brand (domain only, no invented display name): `This web address is a small spelling change away from google.com, so it may be an imitation of that site.` A test pins this wording. The generated list is filtered by the `EXCLUDE` deny-list at generation time, so adult and ad-network domains are never named in a reason.
- mixed script: existing foreign-script reason, with the decoded host appended when it came from `xn--`.

The decoded host is sanitised before it is appended: every control, format (Unicode Cf, including zero-width characters) and bidi control character is replaced by its `U+XXXX` text, and the result is cut to 80 characters with an ellipsis. It is rendered in the existing plain-text node (no `href`). Family warnings stay fixed templates: a test feeds a message with an `xn--` host and a brand name and asserts the Exorcism family warning text contains neither the decoded host nor the brand text from the message (finding 7).

`analyse(input): AnalysisResult` is unchanged, synchronous, and deterministic once the data has loaded. `parseDomain` is sync because `tldts` is sync once its chunk is in memory. The only new public export is `ensureDetectionData(): Promise<void>` from `src/detection/index.ts`. Features keep importing from `src/detection/index.ts`. The index adds exports for `parseDomain` and `decodePunycodeLabel` only if a feature needs them (none does today). ## Bundle budget

Baseline (measured, `.agents/tasks/osb/baseline.md`): main JS 309.22 kB raw / 99.10 kB gzip, main CSS 28.96 kB / 6.20 kB, runtime chunk 0.71 kB gzip, `HauntedBackdrop` 1.51 kB, `Seance` 4.56 kB (+1.57 kB CSS), `src-*.js` 7.29 kB gzip (presumed to be the engine chunk, not verified).

Two separate measures, both reported by `scripts/size-report.mjs` (Node, reads `dist/`):
1. **First-paint gate.** First paint = the files referenced by `dist/index.html` (script tags, stylesheet links, modulepreload links). Their total gzip after minus before must be at most 25 kB. The `detection-data` chunk is not referenced by `index.html` and must not be modulepreloaded, so it is excluded from this gate by construction; a check fails if `index.html` references it.
2. **Lazy chunk ceiling.** The `detection-data` chunk (tldts about 47 kB gzip measured, confusables about 6 kB, brands about 6 kB, so about 59 kB expected) is reported on its own line with a stated ceiling of 75 kB gzip. Exceeding 75 kB fails the check. It loads on idle after first paint and before the first analysis, never before first paint.

The script finds the lazy chunk by name (`detection-data`, set through `build.rollupOptions.output.manualChunks` or the chunk name of the dynamic import in `vite.config.ts`). It runs after tasks 1.3, 2.3 and 3.2 and again in 10.1. Data is plain TypeScript arrays or one string split at load, which compresses well. If the 75 kB ceiling is exceeded, the remedy is to reduce `--top` for the brand list (for example to 500) and to drop confusables entries outside the most common scripts, not to move data back into the main chunk.

## Evaluation script

Command: `npm run eval` runs `tsx scripts/eval/run.ts`. Flags: `--phish <dir>`, `--ham <dir>`, `--smoke`, `--json`.
- Input: every regular file in the folder (non-recursive; `--recursive` is optional). SpamAssassin public-corpus files (easy_ham, hard_ham) are single raw messages named like `00001.<hash>` and normally BEGIN with an mbox-style envelope line such as `From a@b.example  Thu Aug 22 12:36:23 2002`; the Nazario corpus is mbox. Each SpamAssassin folder has a `cmds` file, so extensions are not used. Rule: if the first line starts with `From `, the file is treated as an mbox. The splitter ALWAYS drops the `From ` envelope line of every message before calling `parseEml` (that line has colons and a space and would read as a malformed header), splits further messages on `^From ` lines that follow a blank line, and unescapes `>From ` to `From ` in bodies. A file whose first line does not start with `From ` is one message. Files named `cmds`, files over 20 MB and unreadable files are skipped and listed. Fixtures: (1) a single message that starts with `From a@b.example  Thu Aug 22 12:36:23 2002`, (2) the same message without the envelope line, (3) a multi-message mbox with `>From ` escapes. A unit test asserts that the parsed headers of (1) equal those of (2), and that (3) yields the right message count with bodies unescaped.
- For each message: `parseEml(raw)` then `toAnalysisInput(parsed)` then `analyse(input)`. `toAnalysisInput` is a pure function in `src/features/possession-check/to-analysis-input.ts` (not in `src/email/`, which stays string-only and must not import the engine, per `structure.md`). `PossessionCheck.tsx` calls the same function, so eval and UI build the input identically. The eval imports it from the feature folder (allowed: features may import the engine). The eval calls `await ensureDetectionData()` once at start so it measures the full engine.
- Predicted_Scam is `suspicious` or `likely scam`. Strict mode counts only `likely scam`. Both tables are printed.
- Metrics: precision = TP / (TP + FP), recall = TP / (TP + FN), false-positive rate = FP / (FP + TN). A zero denominator prints `n/a`.
- Test location (review finding 2): Vitest `test.include` in `vite.config.ts` gains `scripts/**/*.test.ts`. The eval's pure logic (`mbox.ts`, `metrics.ts`, `discover.ts`) lives in `scripts/eval/` with `*.test.ts` next to it; tests that touch the file system start with `// @vitest-environment node` and use a temp folder. `structure.md` Tests section gets one line allowing tests next to scripts, and the conformance test folder rules are updated to match. `tests/` still holds only `repo-conformance.test.ts`.
- Conformance updates (review finding 1): `tests/repo-conformance.test.ts` is changed in task 0.5. The expected script list becomes nine names (`build`, `dev`, `eval`, `gen:brands`, `gen:confusables`, `lint`, `preview`, `test`, `typecheck`). The README regex becomes `/npm run ([a-z:]+)/g` and its expected set gains `eval`, `gen:confusables`, `gen:brands`. `tech.md` documents each new script in the same backtick format. The test runs after task 0.5, not only at the end.
- Lint on scripts (review finding 9): `scripts/gen-*.mjs` and `scripts/size-report.mjs` fall under the existing ESLint `scripts/**/*.mjs` Node-globals entry, which already provides `fetch`, `process` and `URL`. Tasks 2.1 and 3.2 run `npm run lint` to confirm. `scripts/eval/*.ts` are covered by the task 0.4 changes.
- Type and lint coverage: `scripts/eval` is added to `tsconfig.json` `include` and `scripts/**/*.ts` to the ESLint Node-globals `files`, so `npm run typecheck` and `npm run lint` cover it (finding 8). The runtime network scan reads only `src/`, so scripts are outside it; `tech.md` states once that `scripts/gen-*.mjs` use `fetch` at development time only.
- Errors: a file that cannot be read or has no message is counted as skipped and listed, and does not stop the run. A message that makes `analyse` throw is counted as skipped with its file name, because the engine must never throw (the property tests cover this).
- The script never prints message content, only counts and file names.
- With no `eval-data/` and no `--smoke`: exit code 2 with a hint to download the corpora. With `--smoke`: runs the fixtures. Fixtures are original, made-up `.eml` files (a few phishing-style and a few normal), with a note that they prove the script works and are not a benchmark.
- Corpora (user downloads): Nazario phishing corpus `https://monkey.org/~jose/phishing/`, SpamAssassin public corpus `https://spamassassin.apache.org/old/publiccorpus/` (easy_ham and hard_ham). Their licences are the user's concern because they are never committed or shipped. `.gitignore` gets `eval-data/`.
- `docs/EVAL.md` holds the latest table with the run date, command, corpus names and counts, and a clear label for smoke versus real runs. The expected state after this work is a smoke table only, with real numbers pending the user's download.

## Error handling

| Operation | Failure | Recoverable | Caller gets | Logging |
| --- | --- | --- | --- | --- |
| `parseDomain` | `tldts` returns null `domain` (IP, `localhost`, no public suffix), or throws | Yes | `{ host, registrable: host, ... }` (the host itself) | None (no message content in logs) |
| `parseDomain` | Detection data not loaded yet (pre-load mode) | Yes | Result from the old suffix table in `domain-fallback.ts` | None |
| `ensureDetectionData` | Dynamic import fails (offline, blocked, chunk 404) | Yes | Promise resolves; pre-load mode stays active; the next call retries | None |

| `findBrandLookalike` | Any internal error | Yes | `undefined` (no flag) | None |

## Invariants and who enforces them

- `analyse()` never throws and is deterministic: enforced in `analyse.ts` by the rules' own guards and by the property tests. `findBrandLookalike` wraps its body in a guard.
- A brand's own domain is never flagged: enforced first in `findBrandLookalike` (step 2) before any similarity test, because that is the cheapest and most certain check.
- No runtime network: the existing conformance test that scans `src/` for `fetch` and friends keeps running. The scripts live outside `src/`.
- Data files match their generator: a test checks each generated file's header fields and that every confusables entry maps to `[a-z0-9]` and no source is ASCII.
- Hook matcher matches its docs: `tests/repo-conformance.test.ts`.
- Dependencies stay pinned: a conformance test rejects `^`, `~` and ranges.

## Testing strategy

Unit: `domain`, `punycode`, `skeleton`, `typosquat` with fixed examples (`paypal.com.secure-login.xyz`, `xn--pypal-4ve.com`, `gooogle.com`, IPs, `localhost`, trailing dot, upper case). Regression: all 821 current tests, including the sample tests that pin each sample's verdict, so false alarms on the genuine samples would show immediately. Integration: Possession Check shows the decoded text (component test), and the production journey and OCR scripts are re-run in the finish task. Not unit-testable here: real-corpus numbers and Kiro power activation, which need the user's data and the Kiro UI.

## Risks

- False alarms from typosquat on small legitimate sites: mitigated by length thresholds and wording, and measured by the eval on SpamAssassin ham when the user supplies it.
- `tldts` size: 47 kB gzip measured, so it lives in the lazy `detection-data` chunk (ceiling 75 kB gzip, separate from the 25 kB first-paint gate). The cost is a short pre-load window, handled by pre-load mode and by awaiting `ensureDetectionData()` before the first user-triggered analysis.
- Idle prefetch on a very slow phone may not finish before the first click; the handler then waits on the promise, and the screen shows its existing busy state for that moment.
- `lookalikeParts` ranges for decoded hosts are offsets into the original host, not the decoded one. Task 2.4 tests highlight ranges on an `xn--` host explicitly.
- Existing expectations may shift where the PSL changes the registrable domain (for example `.co.in`, `.gov.in` stay the same, but rarely used second levels change). Each changed expectation is listed in the journal.
